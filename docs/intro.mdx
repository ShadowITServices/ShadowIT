# Introduction

Welcome to the Shadow IT documentation — an open, non-paywalled body of knowledge
on Microsoft 365, cybersecurity, and IT governance, written for businesses in
regional Australia and anyone running IT to a professional standard.

This isn't a product manual or a sales brochure. It's a reference library: the
runbooks, baselines, and decision frameworks I'd want a client, a peer, or my
future self to have. The hard part of a library this size isn't writing it — it's
organising it so you can find the one page that's actually written for *you*.

## What's in here

The menu on the left has two sections beneath this page.

### [Executing Strategy](/docs/executing-strategy)

The gap between a decision and a Tuesday morning. It's organised on a single
idea: **the core distinction isn't what the technology is — it's who owns the
decision and who carries the risk.** So it splits first by **audience** —
[Business Owners](/docs/executing-strategy/business-owners/strategy),
[Managed Service Providers](/docs/executing-strategy/managed-service-providers/strategy),
[Internal IT Teams](/docs/executing-strategy/internal-it-teams/strategy) — and then
by **altitude**: Strategy (years), Tactical (quarters), Operational (days).

Pick the seat you're sitting in, then the time-horizon you're working at.

### [Script Repository](/docs/script-repository)

The canonical technical layer, and the one place code lives. Production-grade
PowerShell for Windows and the Microsoft 365 workloads — Entra ID, Exchange
Online, SharePoint, OneDrive, Teams, Intune, Purview, Defender — each with the
permissions it needs, what it changes, and how to tell it worked.

Written once and referenced from everywhere else, because three copies of the
same script are three scripts that will drift.

## The private site

There's a third body of documentation that isn't here: internal working notes,
lab configuration, and material that hasn't earned a public page yet. It's
reached from **Private Site** in the top-right of this page, and it will ask you
to sign in.

It isn't a locked folder inside this site, and that's deliberate. A protected
*path* on a static site still leaks its own text — Docusaurus compiles every
page into JavaScript bundles and a search index served from elsewhere on the
same host, so the words survive at two public URLs even when the page is
blocked. The boundary has to be the whole site, which means a separate one.

## A note on currency

Security guidance and Australian regulation both move. Where these pages cite
specific obligations — the Privacy Act, ASD security baselines, APRA standards — they
were accurate at the time of writing, but you should treat them as a starting point
for your own due diligence, not as legal or compliance advice. If you spot
something out of date or wrong, [tell me](mailto:hello@shadowit.com.au) — that's how
a living repository stays honest.
