# SC-300: Microsoft Identity and Access Administrator — 30-Day Study Program

- **Target exam:** SC-300 (skills measured as of 27 April 2026), leading to the [Identity and Access Administrator Associate](https://learn.microsoft.com/en-us/credentials/certifications/identity-and-access-administrator/) certification
- **Time budget:** ~2 h/weekday, ~4 h/weekend day ≈ 75 h total
- **Assumed baseline:** Strong PowerShell, working knowledge of AD DS, M365 admin, basic KQL

Every topic below links to the relevant Microsoft Learn documentation. Read the linked
page, then do the lab — the links are the study material, not a bibliography.

---

## Domain weightings (drive your effort allocation)

| Domain | Weight | Days allocated |
|---|---|---|
| 1. Implement and manage user identities | 20–25% | Days 1–7 |
| 2. Implement authentication and access management | 25–30% | Days 8–15 |
| 3. Plan and implement workload identities | 20–25% | Days 16–21 |
| 4. Plan and automate identity governance | 20–25% | Days 22–27 |
| Review, practice exams, remediation | — | Days 28–30 |

Domain 2 gets the most days — it carries the highest weight and Conditional Access is the most heavily scenario-tested area on this exam.

---

## Day 0 (before you start): Lab environment

You cannot pass SC-300 on reading alone. Build a lab:

1. **Tenant:** [Create a fresh Entra tenant](https://learn.microsoft.com/en-us/entra/fundamentals/create-new-tenant) via the Entra admin center, or use an existing dev/test tenant. The old free M365 Developer Program is restricted; if you have a Visual Studio Enterprise subscription you get a dev tenant through it. Otherwise a free Entra tenant + M365 Business Premium trial works. ([What is Microsoft Entra?](https://learn.microsoft.com/en-us/entra/fundamentals/what-is-entra))
2. **Licensing:** Activate the **Microsoft Entra ID P2 trial** (or Entra Suite trial if available) — mandatory for PIM, ID Protection, access reviews, entitlement management. ([Licensing fundamentals](https://learn.microsoft.com/en-us/entra/fundamentals/licensing))
3. **Azure subscription:** Free trial or PAYG with spending cap — needed for [managed identities](https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/overview), PIM for Azure resources, Log Analytics, [diagnostic settings](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/howto-configure-diagnostic-settings).
4. **Hybrid lab (optional but recommended):** One Windows Server VM running AD DS + [Entra Connect](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/whatis-azure-ad-connect). Hyper-V locally or a small Azure VM (deallocate when not in use).
5. **Tooling:** [`Install-Module Microsoft.Graph`](https://learn.microsoft.com/en-us/powershell/microsoftgraph/installation); install the [Global Secure Access client](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-install-windows-client) on a test VM later in Week 2.
6. **Break-glass account:** [Create one on day 0](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/security-emergency-access), exclude it from every CA policy you build. This is both lab hygiene and an exam objective.

## Daily structure (repeat every study day)

- **Block A (60–90 min):** [MS Learn modules](https://learn.microsoft.com/en-us/training/courses/sc-300t00) + docs for the day's topics
- **Block B (45–60 min):** Hands-on lab in your tenant — do everything in the portal **and** in [Graph PowerShell](https://learn.microsoft.com/en-us/powershell/microsoftgraph/overview) where applicable
- **Block C (15 min):** 10–15 practice questions on today's topic; log wrong answers in an error journal (topic, why wrong, correct concept)

The error journal is your Day 28–30 remediation input. Don't skip it.

## WEEK 1 — Domain 1: User identities (Days 1–7)

### Day 1 — Tenant, roles, administrative units
- Configure tenant properties, user/group/device settings, [company branding](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-customize-branding), [custom domains](https://learn.microsoft.com/en-us/entra/identity/users/domains-manage) (Entra ID + M365 verification flow)
- [Built-in roles](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference) vs [custom Entra roles](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/custom-overview); role assignable scopes; [assign roles](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/manage-roles-portal) and evaluate **effective permissions**
- [Administrative units](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/administrative-units): when to use, [restricted management AUs](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/admin-units-restricted-management), scoped role assignments
- **Lab:** [Create a custom role](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/custom-create) with `microsoft.directory/users/password/update`; create an AU, scope a Helpdesk Admin to it; verify effective permissions with [`Get-MgRoleManagementDirectoryRoleAssignment`](https://learn.microsoft.com/en-us/powershell/module/microsoft.graph.identity.governance/get-mgrolemanagementdirectoryroleassignment)

### Day 2 — Users, groups, custom security attributes
- [User types](https://learn.microsoft.com/en-us/entra/external-id/user-properties) (member/guest), [group types](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups) (security/M365), membership types (assigned/dynamic), group nesting limits, [group expiration](https://learn.microsoft.com/en-us/entra/identity/users/groups-lifecycle)
- [Dynamic membership rule syntax](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership) (memorize operators: `-eq`, `-contains`, `-match`, `-any`), plus [`memberOf` rules](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-rule-member-of)
- [Custom security attributes](https://learn.microsoft.com/en-us/entra/fundamentals/custom-security-attributes-overview): attribute sets, [permissions model](https://learn.microsoft.com/en-us/entra/fundamentals/custom-security-attributes-manage) (who can define vs assign)
- **Lab:** Build dynamic groups from `department` and `userType`; define an attribute set + attribute, assign to users, filter with Graph

### Day 3 — Bulk operations, licensing, devices
- [Bulk create/invite/delete](https://learn.microsoft.com/en-us/entra/identity/users/users-bulk-add) via admin center CSV; same via [`New-MgUser`](https://learn.microsoft.com/en-us/powershell/module/microsoft.graph.users/new-mguser) loops and [Graph batch requests](https://learn.microsoft.com/en-us/graph/json-batching)
- [Group-based licensing](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/manage-group-licenses) (now managed from the M365 admin center), license conflict/error states, [`Set-MgUserLicense`](https://learn.microsoft.com/en-us/powershell/module/microsoft.graph.users.actions/set-mguserlicense) and [PowerShell/Graph licensing examples](https://learn.microsoft.com/en-us/entra/identity/users/licensing-powershell-graph-examples)
- [Device identity](https://learn.microsoft.com/en-us/entra/identity/devices/overview): [Entra registered](https://learn.microsoft.com/en-us/entra/identity/devices/concept-device-registration) vs [Entra joined](https://learn.microsoft.com/en-us/entra/identity/devices/concept-directory-join) vs [hybrid joined](https://learn.microsoft.com/en-us/entra/identity/devices/concept-hybrid-join) — know the decision matrix cold
- **Lab:** Bulk-create 20 users from CSV via PowerShell with error handling; assign licenses via group; join a test VM to Entra

### Day 4 — External identities (B2B)
- [External collaboration settings](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure), guest invite restrictions, guest user access levels
- [Invite flow](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator) (individual, bulk, [self-service sign-up](https://learn.microsoft.com/en-us/entra/external-id/self-service-sign-up-overview)), guest lifecycle
- **[Cross-tenant access settings](https://learn.microsoft.com/en-us/entra/external-id/cross-tenant-access-overview):** [inbound/outbound trust](https://learn.microsoft.com/en-us/entra/external-id/cross-tenant-access-settings-b2b-collaboration), B2B collaboration vs [B2B direct connect](https://learn.microsoft.com/en-us/entra/external-id/b2b-direct-connect-overview), trust settings for MFA/compliant devices
- **Lab:** Invite a guest from a personal tenant; configure cross-tenant access to trust home-tenant MFA; test the difference

### Day 5 — Cross-tenant sync, external IdPs
- [Cross-tenant synchronization](https://learn.microsoft.com/en-us/entra/identity/multi-tenant-organizations/cross-tenant-synchronization-overview): [configuration](https://learn.microsoft.com/en-us/entra/identity/multi-tenant-organizations/cross-tenant-synchronization-configure), provisioning scope, attribute mapping — know it's built on the [provisioning engine](https://learn.microsoft.com/en-us/entra/identity/app-provisioning/user-provisioning)
- [Federation with SAML/WS-Fed IdPs](https://learn.microsoft.com/en-us/entra/external-id/direct-federation), [Google federation](https://learn.microsoft.com/en-us/entra/external-id/google-federation) for B2B
- **Lab:** If you have two tenants, configure cross-tenant sync; otherwise walk the full config in the portal and screenshot each blade

### Day 6 — Hybrid identity I
- [Entra Connect Sync](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-sync-whatis) vs [Cloud Sync](https://learn.microsoft.com/en-us/entra/identity/hybrid/cloud-sync/what-is-cloud-sync) — read the [decision guide and feature comparison](https://learn.microsoft.com/en-us/entra/identity/hybrid/cloud-sync/connect-to-cloud-sync-decision-guide) (group writeback, device writeback, filtering options, agent architecture). Exam loves "which sync tool for scenario X"
- [PHS](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/whatis-phs) vs [PTA](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-pta) vs federation: security posture, DR characteristics, leaked-credential detection (PHS only) — the [choose an authentication method](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/choose-ad-authn) guide is the exam's mental model
- [Seamless SSO](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-sso) mechanics ([Kerberos ticket to AZUREADSSOACC](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-sso-how-it-works))
- **Lab:** If hybrid lab exists: [install Entra Connect with PHS + express settings](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-install-express), then enable [PTA staged rollout](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-staged-rollout). Otherwise: John Savill's hybrid identity video + docs walkthrough

### Day 7 — Hybrid identity II + Week 1 review
- [Migrate from AD FS](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/migrate-from-federation-to-cloud-authentication): [staged rollout](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-staged-rollout), decommission path
- Entra Connect Health: [agents](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-health-agent-install), alerts, [sync insights](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/how-to-connect-health-sync)
- **Review:** 30–40 mixed Domain 1 questions; update error journal
- **Checkpoint:** Can you explain PHS vs PTA vs federation trade-offs, AU vs custom role use cases, and cross-tenant access settings without notes? If not, re-do before Week 2.

## WEEK 2 — Domain 2: Authentication and access management (Days 8–15)

### Day 8 — Authentication methods
- [Authentication methods policy](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-authentication-methods-manage) (the modern one — legacy MFA/SSPR policies are being retired; know the [migration](https://learn.microsoft.com/en-us/entra/identity/authentication/how-to-authentication-methods-manage))
- [Methods](https://learn.microsoft.com/en-us/entra/identity/authentication/overview-authentication): [FIDO2 passkeys](https://learn.microsoft.com/en-us/entra/identity/authentication/how-to-authentication-passkeys-fido2), Microsoft Authenticator ([number matching](https://learn.microsoft.com/en-us/entra/identity/authentication/how-to-mfa-number-match), [additional context](https://learn.microsoft.com/en-us/entra/identity/authentication/how-to-mfa-additional-context)), [certificate-based auth (CBA)](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-certificate-based-authentication), [Temporary Access Pass](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-authentication-temporary-access-pass), [OATH tokens](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-authentication-oath-tokens)
- [Authentication strengths](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-authentication-strengths) (built-in + custom)
- **Lab:** Enable TAP, onboard a test user passwordlessly with a [passkey](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-authentication-passkeys-fido2); create a custom authentication strength requiring phishing-resistant MFA

### Day 9 — MFA, SSPR, WHfB, password protection
- [Tenant-wide MFA settings](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-mfa-mfasettings), [per-user MFA](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-mfa-userstates) vs CA-based MFA (know why per-user is legacy)
- [SSPR](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-sspr-howitworks): [registration and gates](https://learn.microsoft.com/en-us/entra/identity/authentication/tutorial-enable-sspr), [writeback requirements for hybrid](https://learn.microsoft.com/en-us/entra/identity/authentication/tutorial-enable-sspr-writeback)
- [Windows Hello for Business](https://learn.microsoft.com/en-us/windows/security/identity-protection/hello-for-business/) deployment models ([cloud Kerberos trust](https://learn.microsoft.com/en-us/windows/security/identity-protection/hello-for-business/deploy/hybrid-cloud-kerberos-trust) is the modern answer)
- [Entra password protection](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-password-ban-bad): global/custom banned lists, [on-prem agent architecture](https://learn.microsoft.com/en-us/entra/identity/authentication/concept-password-ban-bad-on-premises)
- [Entra Kerberos for hybrid](https://learn.microsoft.com/en-us/azure/storage/files/storage-files-identity-auth-hybrid-identities-enable) (Azure Files scenarios), account disable + [`Revoke-MgUserSignInSession`](https://learn.microsoft.com/en-us/powershell/module/microsoft.graph.users.actions/revoke-mgusersigninsession)
- **Lab:** Configure SSPR for a pilot group; configure banned password list; revoke a session and observe token behaviour

### Days 10–11 — Conditional Access (two full days — highest-yield topic)
- [Policy anatomy](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-policies): assignments ([users](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-users-groups), [target resources](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-cloud-apps), [network](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-assignment-network), [conditions](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-conditions)) → grant/session controls. Start from the [CA overview](https://learn.microsoft.com/en-us/entra/identity/conditional-access/overview)
- [Named locations](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-assignment-network) (IP ranges, countries, trusted locations — see the [block-by-location policy](https://learn.microsoft.com/en-us/entra/identity/conditional-access/policy-block-by-location)), device platforms, client apps, [filter for devices](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-condition-filters-for-devices)
- [Grant controls](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-grant): MFA, authentication strength, compliant device, hybrid joined, ToU, AND/OR logic
- [Session controls](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-session): [sign-in frequency and persistent browser](https://learn.microsoft.com/en-us/entra/identity/conditional-access/howto-conditional-access-session-lifetime), [CAE](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-continuous-access-evaluation) [strict enforcement](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-continuous-access-evaluation-strict-enforcement), app-enforced restrictions, CA App Control
- **[Authentication context](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-cloud-apps)** (tie-in to SharePoint sensitivity labels and PIM; [developer guidance](https://learn.microsoft.com/en-us/entra/identity-platform/developer-guide-conditional-access-authentication-context)), **[protected actions](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/protected-actions-overview)**
- [Report-only mode](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-report-only), [What If tool](https://learn.microsoft.com/en-us/entra/identity/conditional-access/what-if-tool), CA insights workbook, [policy templates and common policies](https://learn.microsoft.com/en-us/entra/identity/conditional-access/concept-conditional-access-policy-common)
- **Lab:** Build: (1) [require phishing-resistant MFA for admins](https://learn.microsoft.com/en-us/entra/identity/conditional-access/policy-all-users-mfa-strength), (2) [block legacy auth](https://learn.microsoft.com/en-us/entra/identity/conditional-access/policy-block-legacy-authentication), (3) [require compliant device](https://learn.microsoft.com/en-us/entra/identity/conditional-access/policy-all-users-device-compliance) for M365, (4) authentication context + protected action for CA policy management itself. Test each with What If, deploy report-only first, review sign-in log CA tab

### Day 12 — Entra ID Protection
- [ID Protection overview](https://learn.microsoft.com/en-us/entra/id-protection/overview-identity-protection): user risk vs sign-in risk; [risk detections](https://learn.microsoft.com/en-us/entra/id-protection/concept-identity-protection-risks) (leaked creds, impossible travel, token anomalies)
- [Risk-based CA policies](https://learn.microsoft.com/en-us/entra/id-protection/howto-identity-protection-configure-risk-policies) vs legacy ID Protection policies (Microsoft's guidance: use CA)
- [Remediation](https://learn.microsoft.com/en-us/entra/id-protection/howto-identity-protection-remediate-unblock): self-remediation via MFA/password change, admin dismiss/confirm compromise — and how to [investigate risk](https://learn.microsoft.com/en-us/entra/id-protection/howto-identity-protection-investigate-risk)
- [MFA registration campaign](https://learn.microsoft.com/en-us/entra/identity/authentication/how-to-mfa-registration-campaign), [risky workload identities](https://learn.microsoft.com/en-us/entra/id-protection/concept-workload-identity-risk) (requires Workload ID Premium)
- **Lab:** Create user-risk and sign-in-risk CA policies; simulate risk with Tor browser sign-in; investigate and remediate in the Risky users blade

### Day 13 — Global Secure Access
- [Architecture](https://learn.microsoft.com/en-us/entra/global-secure-access/overview-what-is-global-secure-access): SSE, [traffic forwarding profiles](https://learn.microsoft.com/en-us/entra/global-secure-access/concept-traffic-forwarding) ([Private Access](https://learn.microsoft.com/en-us/entra/global-secure-access/concept-private-access), [Internet Access](https://learn.microsoft.com/en-us/entra/global-secure-access/concept-internet-access), M365)
- [GSA client deployment](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-install-windows-client), [Private Access app segments](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-configure-per-app-access) vs [Quick Access](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-configure-quick-access), [Entra Private Network Connector](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-configure-connectors)
- Internet Access [web content filtering](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-configure-web-content-filtering), universal CA / [compliant network check](https://learn.microsoft.com/en-us/entra/global-secure-access/how-to-compliant-network)
- **Lab:** Deploy GSA client on a test VM, enable the M365 profile, create a Private Access app to an internal RDP/SMB target if you have the hybrid lab

### Day 14 — Domain 2 consolidation lab
- Full scenario build: zero-trust baseline (block legacy auth, require MFA all users, phishing-resistant for admins, risk policies, compliant device for sensitive apps, [break-glass exclusions](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/security-emergency-access) everywhere)
- Troubleshoot deliberately: lock a test user out, [diagnose via sign-in logs → CA tab](https://learn.microsoft.com/en-us/entra/identity/conditional-access/troubleshoot-conditional-access)

### Day 15 — Domain 2 review
- 40–50 mixed questions on auth + CA + ID Protection + GSA; error journal
- **Checkpoint:** Given a scenario table (user, location, device, app), can you predict which CA policies apply and the resulting access decision? This is the core exam skill — the [CA deployment planning guide](https://learn.microsoft.com/en-us/entra/identity/conditional-access/plan-conditional-access) is good revision.

## WEEK 3 — Domain 3: Workload identities (Days 16–21)

### Day 16 — Identity types for workloads
- [Workload identities overview](https://learn.microsoft.com/en-us/entra/workload-id/workload-identities-overview) — decision matrix: system-assigned MI vs user-assigned MI ([managed identities](https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/overview), [best-practice guidance](https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/managed-identity-best-practice-recommendations)) vs [service principal](https://learn.microsoft.com/en-us/entra/identity-platform/app-objects-and-service-principals) vs user account vs (group) managed service accounts
- **Lab:** Create both MI types; assign to a VM/Function; [use the VM's MI to reach Azure services](https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/tutorial-windows-managed-identities-vm-access) — read a Key Vault secret and list a storage container ([`Connect-AzAccount -Identity`](https://learn.microsoft.com/en-us/powershell/module/az.accounts/connect-azaccount))

### Day 17 — Enterprise applications
- [App registration vs enterprise application](https://learn.microsoft.com/en-us/entra/identity-platform/app-objects-and-service-principals) (application object vs service principal) — this distinction underpins half of Domain 3. See also [what is application management](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/what-is-application-management)
- Tenant-level settings ([user consent settings](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/configure-user-consent), [admin consent workflow](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/configure-admin-consent-workflow)), app-level settings (assignment required, visibility)
- Roles: [Application Administrator vs Cloud Application Administrator](https://learn.microsoft.com/en-us/entra/identity/role-based-access-control/permissions-reference) vs owner
- [App collections (My Apps)](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/access-panel-collections), [assigning users/groups/app roles](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/assign-user-or-group-access-portal)
- **Lab:** [Add a gallery SaaS app](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/add-application-portal), [configure SAML SSO](https://learn.microsoft.com/en-us/entra/identity/enterprise-apps/add-application-portal-setup-sso) with [claims customization](https://learn.microsoft.com/en-us/entra/identity-platform/saml-claims-customization), require assignment, assign via group

### Day 18 — Application Proxy + SaaS integration
- [App Proxy architecture](https://learn.microsoft.com/en-us/entra/identity/app-proxy/overview-what-is-app-proxy): [connectors](https://learn.microsoft.com/en-us/entra/identity/app-proxy/application-proxy-conceptual-connectors), connector groups, pre-authentication (Entra vs passthrough), [KCD for SSO to IWA apps](https://learn.microsoft.com/en-us/entra/identity/app-proxy/how-to-configure-sso-with-kcd)

### Day 19 — App registrations
- [Register an app](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-register-app): single vs multi-tenant, [redirect URIs](https://learn.microsoft.com/en-us/entra/identity-platform/reply-url), [certificates vs secrets](https://learn.microsoft.com/en-us/entra/identity-platform/how-to-add-credentials) (and why certs win), [federated credentials](https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation)

## Exam-technique notes

- Scenario questions usually hinge on **least privilege** and **lowest licence that satisfies the requirement** — when two answers both work, pick the cheaper/lesser-privileged one
- "Minimize administrative effort" = the most managed/automated option (Cloud Sync over Connect where features allow, dynamic groups over assigned, group-based licensing, access packages over manual assignment)
- Know [licence gates](https://learn.microsoft.com/en-us/entra/fundamentals/licensing): P1 (CA, group-based licensing basics), P2 (PIM, ID Protection, access reviews, entitlement management), Workload ID Premium (workload identity risk, CA for workload identities), Entra Suite (GSA Private/Internet Access + governance bundle)
- Case studies: read the requirements first, then mine the environment description only for what each question needs
